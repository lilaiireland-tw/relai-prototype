# Initial CEFR-J starter selection (Issue #65)

`POST /relaiapp/api/v1/onboarding/level` accepts exactly `{ "english_level": "A1" | "A2" | "B1" | "B2" }`. It requires the existing session cookie and completed password change. The user ID always comes from that session. The endpoint returns `english_level`, `starter_cards_created`, and `already_selected`; repeated selection of the same level returns zero new cards. An attempt to choose a different level after initial selection returns `409 LEVEL_ALREADY_SELECTED`. A later level-change feature is separate and must not start another full pack automatically.

The first request persists the selected `user_settings.english_level` and creates exactly 20 Catalog links for that level. `src/worker/persistence/starter-pack.ts` maintains four fixed lists of 20 canonical IDs; B1 retains its original IDs. Onboarding reads complete lexical content directly from D1 by these IDs, with no runtime JSON, Catalog INSERT/UPDATE, lexical-content copying or Gemini call. Every entry must be published, shared, CEFR-J 1.6, of the selected level, and have a headword, POS, sense key, Chinese definition, English example and Chinese example translation. A missing/incomplete/ineligible entry returns `503 CATALOG_UNAVAILABLE` before any level/card/stat changes.

D1 revalidates the entire selected pack, inserts missing cards, updates the actual created-card counter, and claims the initial level in one prepared-statement batch transaction. The insert runs only while the user has no selected level. A concurrent Catalog eligibility change aborts the batch (500, safe to retry after repair), leaving cards, stats and level untouched. Per-user unique indexes protect against duplicates. Invalid bodies return 400; no session returns 401; password change required returns 403. Existing users are returned before Catalog validation and retain cards, reviews, favorites and statistics.

The ID lists retain shuffled order. The existing Cards API/UI still sorts by its established created-at/ID rules; this change does not guarantee the same presentation order as the whitelist. Populate and verify all 80 entries through the separately authorized [one-time import](catalog-112/runbook.md) **before enabling this Worker version**. The original B1 JSON remains solely for legacy importer compatibility and offline identity verification.
