# Initial CEFR-J starter selection (Issue #65)

`POST /relaiapp/api/v1/onboarding/level` accepts exactly `{ "english_level": "A1" | "A2" | "B1" | "B2" }`. It requires the existing session cookie and completed password change. The user ID always comes from that session. The endpoint returns `english_level`, `starter_cards_created`, and `already_selected`; repeated selection of the same level returns zero new cards. An attempt to choose a different level after initial selection returns `409 LEVEL_ALREADY_SELECTED`. A later level-change feature is separate and must not start another full pack automatically.

The first request persists the selected `user_settings.english_level` and materializes the same 20 reviewed B1 demo entries from `data/ai-enrichment/b1-sample-20.json` for every level choice. The shared catalog is not modified by onboarding. Cards store the approved catalog IDs and normalized keys; complete lexical content is read from the catalog. A missing or incomplete demo catalog returns `503 CATALOG_UNAVAILABLE` without saving the level. Populate the demo rows through the guarded catalog importer before onboarding.

D1 executes the level claim, card insert, and created-card counter update in one prepared-statement batch transaction. The insert runs only when the level claim changed one row. This prevents a retry or concurrent request from selecting another batch, while the per-user unique indexes protect against duplicates. Invalid bodies return 400; no session returns 401; password change required returns 403.
