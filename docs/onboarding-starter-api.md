# Initial CEFR-J starter selection (Issue #65)

`POST /relaiapp/api/v1/onboarding/level` accepts exactly `{ "english_level": "A1" | "A2" | "B1" | "B2" }`. It requires the existing session cookie and completed password change. The user ID always comes from that session. The endpoint returns `english_level`, `starter_cards_created`, and `already_selected`; repeated selection of the same level returns zero new cards. An attempt to choose a different level after initial selection returns `409 LEVEL_ALREADY_SELECTED`. A later level-change feature is separate and must not start another full pack automatically.

The first request persists `user_settings.english_level` and materializes up to `STARTER_BATCH_SIZE` (currently 100) entries from **CEFR-J Vocabulary Profile 1.6**, at exactly the selected level. Selection sorts by normalized key and catalog ID, taking one row per key before applying the limit. An existing personal card with one of those keys is preserved and skipped. The shared catalog is not modified. The card stores the catalog ID and normalized vocabulary key; available POS and ReLai enrichment are copied. When no definition or example exists, the required `back_content` displays only a CEFR-J level/POS label, without inventing a Chinese translation.

D1 executes the level claim, card insert, and created-card counter update in one prepared-statement batch transaction. The insert runs only when the level claim changed one row. This prevents a retry or concurrent request from selecting another batch, while the personal `(user_id, vocabulary_key)` and `(user_id, vocabulary_catalog_id)` unique indexes protect against duplicates. If the requested level has no catalog rows, the endpoint returns `503 CATALOG_UNAVAILABLE` and does not persist the level. Invalid bodies return 400; no session returns 401; password change required returns 403. No frontend onboarding or general Cards API is included here.
